Tablet handle drags: keep the curve planar, drag in its plane

~/notes/tasks/autodraw_ipad/plan-tablet-planar-handle-drags.html. All questions resolved; see Implementation at the bottom.

Why it feels broken

The free-handles refactor (2026-09-02) kept an invariant: d0, d3 and the chord stay coplanar. So on every pen move, the handle you are not dragging gets swung into the plane the dragged handle now spans with the chord. Your pen moves in the camera plane, which tilts that plane on nearly every move, so the other handle is rotated about the chord every frame. For an S-curve (handles on opposite sides of the chord) that rotation shows up on screen as the other handle going the opposite way.

Decision (Q1): the curve stays planar. So the fix is the drag, not the invariant: a handle drag must move the handle inside the stroke's current plane, so the plane never changes mid-drag and the other handle never moves. Changing the plane becomes its own, deliberate action.

Resolved

Q2 → keep move_vertex; Q3 → no format bump; Q4 → pen ray ∩ stroke plane; Q5 → ignore the move below |cos| 0.15; Q6 → camera-facing plane for straight strokes; Q8 → tilt = sticky toggle, handle drag uses camera-plane drag + swing (all 2026-09-03, recommendations taken).

Q1 → curves stay planar (2026-09-03). Two independent 3D handles rejected.

Q7 → tilt button (2026-09-03). Handle drags never roll the plane by themselves: with the curve planar and p0/p3 fixed, a handle leaving the plane forces the other handle to move by the same y·tanθ, opposite way on an S-curve. So rolling the plane is an explicit, armed action; the gesture is Q8.
